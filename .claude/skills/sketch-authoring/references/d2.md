# D2 recipes for sketch tiles

Every snippet here compiles with the board's renderer (`@d2lang/d2`, ELK layout). Tiles render in
**sketch (hand-drawn) mode by default**. For contracts and schemas, put
`vars: { d2-config: { sketch: false } }` on the first line so they read crisp.

Natural sizes listed below are what each recipe renders at. Give the tile at least that much `width` in
`board.canvas`.

## HLD: components and flows (~1200 × 250, left to right)

```d2
direction: right

rider: Rider { shape: person }
api: API
dispatch: Dispatch {
  style.stroke: "#e8590c"
  style.stroke-width: 3
}
supply: Supply index { shape: cylinder }
queue: Offer events { shape: queue }

rider -> api: requests Trip
api -> dispatch: dispatch Trip
dispatch -> supply: nearby Drivers
dispatch -> queue: Offer { style.stroke-dash: 4 }
```

- The orange, thick stroke marks the center of gravity. Dashed means async.
- Useful shapes: `person`, `cylinder` (store), `queue`, `cloud` (external), `page`, `hexagon`, `diamond`.
- Wider than about 1100 px? Use `direction: down`, or split the HLD.

## Sequence: order, retries, timeouts (~460 × 740, tall)

```d2
shape: sequence_diagram
rider: Rider
dispatch: Dispatch
driver: Driver
rider -> dispatch: request Trip
dispatch -> driver: Offer (10s)
loop: until accepted {
  driver -> dispatch: decline / timeout
  dispatch -> driver: next Offer
}
driver -> dispatch: accept
dispatch -> rider: Match
```

The participants are the declared keys, in order. A nested map (`loop: …`) draws a labelled group.

## Lifecycle: state machine (~880 × 240)

```d2
direction: right
requested: Requested
offering: Offering
matched: Matched
cancelled: Cancelled { style.stroke-dash: 3 }
requested -> offering: Candidates found
offering -> offering: Offer expires
offering -> matched: Driver accepts
offering -> cancelled: no Driver
```

## Aggregate + invariants (~580 × 520)

```d2
trip_agg: Trip {
  shape: class
  id: TripId
  "driver?": DriverId
  "+offer(driver, ttl)": Offer
  "+accept(offer)": Match
}
rules: |md
  **Invariants**
  - one live Offer per Trip
  - a Driver holds at most one Match
|
trip_agg -- rules: { style.stroke-dash: 3 }
```

- Fields are `name: Type`. **Methods must be quoted** and use no `:` inside the parentheses:
  `"+offer(driver, ttl)": Offer`. Unquoted `+offer(d: DriverId): Offer` gets split at the first colon.
- The `+` / `-` prefix shows visibility. A `?` in a quoted key means optional.
- Put the aggregate and its lifecycle in one file when the lifecycle is the point:
  `trip_agg -> lifecycle: moves through`, with `lifecycle: Trip lifecycle { … }` holding the states.

## Schema + access pattern (~650 × 270, crisp)

```d2
vars: { d2-config: { sketch: false } }
direction: right
trips: {
  shape: sql_table
  id: uuid { constraint: primary_key }
  driver_id: uuid { constraint: foreign_key }
  state: text
  version: int
}
drivers: {
  shape: sql_table
  id: uuid { constraint: primary_key }
  status: text
}
trips.driver_id -> drivers.id
idx: |md
  **Index** `(state, created_at)`: the open-Trips sweep
| { shape: text }
```

- Constraints: `primary_key`, `foreign_key`, `unique`. Link columns with `table.col -> other.col`.
- Non-SQL layouts work too: use a `sql_table` with quoted keys, such as
  `"cell → driver_id": set` and `"driver:{id}": "lat, lng, ts"`.
- Always add the access-pattern note (the query, key or index on the hot path).

## Contracts as code (~550 × 230)

Inside D2, use a code block whose language tag follows the first `|`:

```d2
port: |ts
  interface SupplyIndex {
    nearby(at: Location, radiusM: number): DriverId[]
  }
|
union: |||ts
  type Status = 'online' | 'offline'
|||
```

Use `|||` when the code itself contains `|`. For several ports, a `.md` tile with a ` ```ts ` block is often
simpler and reads better than D2.

## Markdown inside D2

```d2
note: |md
  **Invariants**
  - a ShortCode is never reassigned
|
title: |md # Dispatch | { near: top-center }
legend: |md dashed = async | { near: bottom-right }
```

`shape: text` removes the box. `near: top-center | bottom-right | …` pins text outside the layout.

## Trade-off side by side (~800 × 70)

```d2
grid-columns: 2
greedy: |md
  **Greedy**
  Offer per Trip, now. Fast, locally optimal.
|
batch: |md
  **Batch ~2s**
  Solve a matching. Better globally, adds latency.
|
```

## Staged reveal: `steps`

```d2
direction: right
a: Rider
b: Dispatch
a -> b: request
steps: {
  1: {
    c: Driver
    b -> c: Offer
  }
  2: {
    c -> b: accept
  }
}
```

The base board shows first. Each step adds to the one before it, and the tile gets ◀ ▶ controls. Use this
for a story ("happy path, then the timeout"), not to hide content.

## Gotchas

- **Reserved keywords can't be keys** (case-insensitive): `link`, `label`, `shape`, `style`, `icon`,
  `tooltip`, `near`, `width`, `height`, `class`, `classes`, `direction`, `constraint`, `vars`, `steps`,
  `layers`, `scenarios`, `top`, `left`, `grid-rows`, `grid-columns`. Use another key and set the label:
  `link_agg: Link { shape: class }`.
- A key with spaces or symbols needs quotes: `"Supply index": …`, or use `supply: Supply index`.
- `a -- b` draws an undirected line, and `a <-> b` draws arrows both ways.
- Multi-line labels use `label: "Supply index\n(in-memory)"`, or `\n` inside a quoted label.
- Keep one idea per file. A D2 error only breaks its own tile, but a giant file makes one error cost a lot.
